# Desktop architecture and operating notes

## Trust boundary

`desktop/main.mjs` owns native dialogs, bounded file I/O and Codex processes. The renderer loads only bundled assets through `fox24://app/`. Node integration is off; sandbox and context isolation are enabled. Navigations, popups, webviews, permission requests and renderer network requests outside the packaged origin are denied. The preload exposes named operations, never generic IPC, shell or filesystem access. Every IPC request verifies its main-frame sender and validates the payload.

`desktop/codex.mjs` discovers the native executable across PATH, Homebrew, npm, NVM, Cargo and common Windows install locations. It resolves npm shims to the native binary instead of spawning `.cmd` or using a shell. Prompts travel over stdin; the task model comes from a fixed economy allowlist rather than renderer input or the CLI default. Up to four tasks can run. Each has an independent workspace, cancellation controller, ten-minute deadline and output cap. Process groups (POSIX) or taskkill trees (Windows) are terminated on cancellation. No unsafe sandbox-bypass flags are used.

CLI discovery probes version compatibility before choosing an implicit executable, deduplicates native paths and skips older CLI copies injected by a launcher’s node_modules/.bin PATH. Explicitly configured paths remain authoritative, and an old-only installation still reports an upgrade requirement. In particular, PandaGO’s 0.159.3 dependency must not shadow a compatible user-installed CLI. Connection labels distinguish missing CLI, old CLI and missing login.

Codex >=0.164.0 is required for config isolation and native image generation. `codex exec --json` currently does not expose native image items; the adapter consumes only newly modified regular files from `CODEX_HOME/generated_images/<thread.started ID>`. It never picks the newest global image or a path mentioned in prose. After the CLI completes, the adapter waits up to three seconds for that exact thread's image file to finish appearing, without sending another model request; cancellation remains responsive during this wait. Model prose such as ‘no image returned’ does not override an actual validated image file. A no-image response says that this request produced no new image and preserves the previous result, rather than asserting that the CLI or account is unsupported. `last-generation.json` in user data retains only the latest task/model/thread/outcome/timing metadata for diagnosis, with no prompt, reference or image bytes. It also accepts validated native image event payloads if a later CLI emits them. Missing images and incomplete turns fail visibly.

The application supplies no API endpoint, key or billing backend. It uses `forced_login_method="chatgpt"` and ignores user provider configuration. Codex itself connects to OpenAI. Model availability is checked against the account catalogue. The backend chooses `gpt-6-luna`, then `gpt-5.6-luna` if the former is absent; these documented economy models support image input and the native image-generation tool. Catalogue failure or an expensive-only catalogue blocks requests instead of inheriting a default. The browser/PandaGO web preview has no Electron preload bridge and does not display a native-connection failure banner; actual AI work uses the spawned desktop window. Development accepts `PORT` or `--port`, with 5173 as the fallback. The HTTP listener, Electron URL, exact trusted origin, websocket allowlist and CSP must all share that chosen loopback origin. Packaged builds ignore development URLs; remote hosts, credentials, query/hash and non-root paths cannot become trusted development origins. Connected and initial-checking states display no Codex status or success message. A confirmed missing/old CLI, missing login, unavailable model catalogue or detection failure displays the sole permitted banner below the title bar, with its actionable diagnostic. Keep it visible during rechecks until a successful connection result removes it; no manual status dropdown, chevron or CLI picker. Detection runs on mount and when the app regains focus or becomes visible, coalesces overlapping checks, and skips active artwork/polish jobs. Failed detection updates the disconnected state instead of retaining a stale ready flag; its diagnostic appears directly in the disconnected banner. There is no manual model selector; legacy saved model choices are removed from renderer settings and cannot override backend routing. No paid Fast/Priority tier is enabled. Native generation availability is established only by successful image output; the image tool itself remains managed by Codex, so this policy controls the orchestration model rather than claiming control over its underlying image-model billing.

Reference-animation constraints live in `animation-prompt.mjs`. With a source image, the compiler preserves identity, face design, hairstyle, costume, palette, linework, background, baseline scale and fixed-camera framing. It distinguishes those design constraints from pose: unless the user requests subtle/local motion, use visible body/contour changes, a readable peak pose and natural follow-through within the original frame. Do not freeze subject position or force the entire movement into tiny increments. Respect explicitly subtle motion and avoid inventing limbs outside the source crop. Explicit user edits override the corresponding appearance or camera constraint; text-only generation retains its broader creative motion policy. The generic text-only camera/deformation/visual-impact directives previously conflicted with fixed-camera reference requests and must not be added to reference-animation prompts.

For Codex 0.164, `--image` supplies an image to the task model, while the image tool exposes `referenced_image_paths` for the editing input. The task instructions and generation prompt therefore specify the actual temporary original-file path in that argument, and name the supported `image_gen.imagegen` / `tools.image_gen__imagegen` invocation rather than requiring a nonexistent function spelling. A text description of the source or a promise to preserve it is insufficient: a real prompt-only test still redesigned the face and framing. Do not invent image-tool `input_fidelity` settings that its schema does not expose. The API's [input-fidelity documentation](https://developers.openai.com/api/docs/guides/image-generation#image-input-fidelity) describes a separate interface.

Regression checks verify that the prepared square reference bytes, explicit image-tool path argument and preservation policy reach the CLI, and that reference prompts do not inherit text-only creative expansion. Visual acceptance must compare the original, previous result and new frames under the same task model; a request succeeding or a mock passing does not establish identity preservation. In the real GPT-6 Luna check, the prompt-only revision still redesigned the face, hair and crop, while explicitly including the source path produced a 24-frame sheet that visibly retained the source identity and framing. This one sample supports the input-path fix; it does not establish pixel-identical output or a general model-quality ranking. `last-generation.json` records whether a reference was attached and the prompt-policy version without retaining the image or prompt there. A historical same-reference, same-GPT-6-Luna A/B run (before prompt suggestions were removed) of the motion policy used the first suggestion from each strategy without hand-picking: the old sheet repeated essentially the same pose, while `preserve-reference-motion-v3` showed a shoulder/neck anticipation, an upward release and a broad hair follow-through before returning. Image generation took about 52 and 62 seconds in this run. These are single-run observations, not a latency or quality guarantee.

## Persistence and recovery

GifHop retains the legacy `com.bavoch.fox24` app ID, `fox24://` origin, `window.fox24` bridge and `fox24` user-data directory so existing installations keep their settings and recovery data. The product name and installer filenames are GifHop.

The preview workspace has two equal square panes, sized to fit the available width and height. Both reference and result images fill their square panes edge to edge, with no inset or inner padding. Use centered `object-fit: cover` without stretching and inherit the pane’s rounded corners. The left accepts and displays a reference image, and the right plays the generated animation. Replacing or removing the reference preserves the result; generation progress stays in the right pane. Reference replacement/download/removal appears inside the left image on hover or keyboard focus; playback appears at the center of the right preview. Touch devices keep these controls visible. A split primary export button always remains visible at the right of the title bar, including an empty workspace and after deleting a result. With no result, both segments are disabled rather than hidden. It starts with “导出 GIF” each launch; the main segment exports the chosen format and the right arrow opens GIF/WebP/video and pixel-size options. Choosing a format only updates the label, never starts an export. Both segments lock during export or generation, while the main segment shows export progress. Keep its label visible at narrow widths and its two segments adjacent with one shared outer shape; keyboard order follows main action then format picker. The prompt composer sits underneath the previews. Its generation action and the title-bar export action use the same small button size, without a separate minimum-height override, so their heights stay aligned across viewport sizes and running states. The accent and focus colors match the logo’s yellow-green background. Frame thumbnails and position editing are removed. Manual sprite-sheet import is removed, including its title-bar button, file input and renderer handler. Only reference-image upload remains. Manual project open/save actions, their preload methods and IPC handlers are removed; materials and the current workspace are saved automatically.

Only the current result and reference are persisted. The main process stores them as content-addressed files in `draft-assets/` and writes `recovery.json` with their keys, the composer prompt, the reference crop and the result's read-only offsets and title. Identical image bytes are deduplicated. Writes sync the temporary file, rename it atomically, and sync the containing directory where supported. After each checkpoint, assets that are no longer referenced are pruned, so replacing or deleting a result does not leave earlier results on disk. The application waits for the queued checkpoint write on exit.

The result pane exposes deletion directly in its bottom-right corner, with no intermediate more-actions menu. Deletion clears the preview, immediately checkpoints the empty result so a quick restart cannot reopen it, and finishes silently without a success notice or undo banner. The delete button shows its own pending state and rejects repeated clicks. Removing a result also prunes its sheet asset from `draft-assets/`; the reference and composer text stay untouched.

Version history is removed: no result-pane navigation, material library, trash, rename or archive endpoints, and no `history:*` IPC or preload methods. Do not reintroduce historical-version switching under another name. The result pane shows only the current animation, its playback control and direct deletion. Restoration commits the saved sheet, its read-only offsets, the reference (including none) and the prompt together and resets playback to the start; it invalidates pending reference reads, and a failure keeps the previous complete view.

The checkpoint format stores the current prompt, reference crop/title, and one slot with the sheet asset key, read-only offsets, title and originating prompt. Legacy version-1 recovery data is still read for its first inline sheet so an older draft can be recovered once; removed version IDs and history lists in older checkpoints are ignored, and their version-library files are no longer used by the app. No project-file dialogs or renderer operations are exposed. Native export dialogs keep arbitrary destination paths out of the renderer.

The last idle editing state is saved after a 700 ms debounce in Electron's user-data directory (`recovery.json`). This compact checkpoint references asset keys rather than copying image blobs. Ordinary startup offers restoration rather than silently replacing the canvas; declining restoration leaves the local draft files in place. Unreadable checkpoints are backed up before replacement; if backup fails, automatic overwrite is blocked. Development code restarts request an immediate renderer checkpoint, wait for it to finish, and restore the project automatically in the new window without a recovery prompt or success banner. A failed checkpoint aborts the automatic restart and keeps the current window. The restore flag is accepted only for the local development origin, never in packaged builds. An abrupt OS shutdown within the debounce can lose recent draft edits. Unfinished AI tasks are not resumed after restart; generation source files already produced remain in Codex's own directory. GifHop doesn't delete the user's Codex history or images.

If a checkpoint write fails, the in-memory result stays visible and the inline error reports the failure; the next idle save retries. Preview decoding failures keep the prompt and reference intact. Browser-only development previews persist the whole draft in IndexedDB instead of using the native asset store.

## Failure handling

Non-square references start with a centered square crop and can be panned directly in the input pane using mouse, pen or touch. Pointer capture keeps the drag active outside the pane; clamp movement to the image edges so no empty area enters the frame. The same focusable control supports arrows (1%), Shift+arrows (10%), Home/End (edges), and Escape (center). Square sources have no overflow and expose no panning control. Generation/polishing lock movement until the request ends; dragging never calls AI. Keep the pane square and edge to edge without extra crop panels or permanent instructions.

`reference-crop.mjs` provides the shared normalized source position and crop bounds. CSS object-position and `src/reference-image.js` use the same 0–1 coordinates so the displayed viewport and actual AI pixels agree at every window size. Before generation or polishing, extract only the selected region as a square PNG; square inputs retain their original bytes. Rectangular crops are capped at 4096px per side and resized if necessary to fit the existing 8MB limit, preserving transparency. Retain the full original plus `referenceCrop` in the local draft, allowing further adjustments after generation. The main process receives only the prepared square `referenceImage`, never the editable source. Never replace the editable source with its cropped derivative. Draft restoration keeps its own crop position. Legacy records without crop metadata default to center, with no bulk rewriting. Prompts must preserve the selected square framing and forbid restoring hidden content or adding letterboxing. Headless pixel checks cover mouse/touch panning, clamping, keyboard focus, source preservation, save/reload, image-only generation and polishing; they do not establish a new real-model generation-quality result.

The left image has a download action beside replace/remove for generated and uploaded references. Export the current square viewport using the same crop preparation as generation, retaining square source bytes/format where possible and using PNG for rectangular crops. Its filename comes from AI understanding of that actual static image, for example `举旗的橘猫.png`, with a preferred 4–8 Chinese characters and an enforced maximum of 12 Unicode characters. Send only the prepared image with `target: "reference"` to the title bridge; the `image-title` task inspects one static picture with tools/image generation disabled and no current composer prompt or sprite-sheet assumptions. Never reuse an animation title for a reference download or fall back to a generic filename when naming fails.

Cache the successful title against the prepared image’s content hash in `referenceTitle`, and preserve it through draft recovery and portable backup. The next download recomputes the hash: an unchanged picture reuses its title (including after a cancelled save or offline restart), while different visible crop pixels require fresh naming. Replacing a source resets its local title metadata. Initial naming requires the desktop AI bridge; a cached title needs no AI connection. Keep the download icon pending across naming and saving, prevent duplicate activation, and keep success/native-save cancellation silent; errors use the existing inline feedback. Neither naming nor downloading changes the source, crop, prompt, existing result or animation metadata. A real GPT-6 Luna static-image naming check of the reference cat illustration returned `举旗的橘猫` (5 characters); fixture-based browser checks cover crop-specific naming, cache/recovery, offline reuse and retry.

Reference upload, replacement and removal are local operations: they never request AI image understanding, prefetch prompts, or overwrite the composer. Prompt generation, variation queues and their renderer hook, vendored action controller, IPC/preload/client endpoints, JSON parsers and policy module are removed. Do not reintroduce an automatic AI request on upload, reconnect or draft restoration.

With text and no reference, one Generate Animation action runs two sequential native image jobs: `codex:reference` / `CodexService.run("reference")` creates one static square starting image, then the ordinary animation job uses those actual image bytes as its reference. The reference stage must not produce a sprite sheet or storyboard. It uses the same automatic economy routing and low reasoning effort as animation generation. Normalize the returned image to a square within the existing 8MB input limit, commit it to the left pane, and durably checkpoint it before starting animation. The automatic animation chain does not pause for review or require another click. Existing uploaded, restored or previously generated references skip the first stage. The static image is a saved reference, never a generated animation result.

A separate “生成参考图” button sits immediately left of “生成动画”. It always creates a fresh static reference from the current nonempty prompt, using the same reference-stage implementation, and returns after displaying/checkpointing that image; it must never call animation generation. A successful operation replaces only the left reference and resets its crop to center, preserving the right result and its metadata. Failure or cancellation before a new image completes preserves the previous input and result. The same button becomes the reference cancellation action while running, stays pending until the stage (including checkpoint persistence) settles, and is mutually exclusive with animation, polishing and export. Empty prompts and a disconnected state disable the static-image action. Generated references can then be reused by the animation action without another reference job. Headless checks cover the button’s placement/keyboard order, standalone behavior, failure/cancellation, preservation, persistence boundary, recovery and 375px/560px layouts.

Keep the main generation button cancellable across both stages. Use distinct stage IDs and ignore stale progress; show reference progress only in the left pane and animation progress only in the right pane. A cancel acknowledgement must not restore the idle action before the active promise settles. Check cancellation again after reference persistence and crop preparation so a stop at the boundary cannot launch animation. Completed references survive animation failure/cancellation and restart; explicit retry reuses them. There is no automatic retry or second reference job after an animation failure. Headless checks cover both stage failures, retained prior results, retry, cancellation during either stage and at the save boundary, and recovery. A separate real GPT-6 Luna reference-only request returned a single 1254×1254 cat illustration (about 1.38MB) in about 30.3 seconds; the picture was visually checked as a single composition. That sample validates the new static-image stage, not a new real-model two-stage animation-quality or latency guarantee.

An empty composer is sent and archived as an empty string. The backend detects image-only generation and uses the separate `reference-creative-v3` route. Interpret the image’s subject, setting, mood and visual cues, then use a visible detail to set a short visual story in motion. Build from a clear cause and effect to a visually tense climax and a natural return to the start. Keep the original subject and style recognizable across a continuous 24-frame loop. Use readable in-between poses, believable weight and follow-through, and match motion through the loop seam. Carry the reference’s palette, lighting and texture through each frame, with clear silhouettes and composition that guides attention. It must not inherit the explicit-edit route’s fixed camera, frozen geometry or “no unspecified actions” clauses. Both the native tool guide and compiled prompt use that distinction; preserving only the blank frontend value is insufficient. The original reference path is still explicitly supplied to the image tool. Polishing and text-only generation continue to reject empty input. Blank prompts stay blank after restoration. The internal default intent never populates the composer: when reading a saved draft or recovery checkpoint, an exact match to that legacy fallback becomes an empty input; other user text stays intact. Keep the ordinary action-description placeholder. A real same-reference GPT-6 Luna check of the earlier `reference-creative-v1` route returned a 24-frame sheet in about 49.5 seconds and independently developed a crescent-earring interaction, compared with the recent result’s repeated body sway. This is one visual sample, not a general quality or latency guarantee. The composer contains manual input, polishing and artwork generation, with no hint/status row or prompt-switching shortcuts. Focusing or typing in the prompt keeps its border, background and shadow unchanged, without an activation outline; this is scoped to the composer text input, not global control focus styling. Polishing is available only for nonempty text and cannot serve as an alternate image-only prompt generator. The same polish button changes to “取消” while running; never append a separate cancel-task button. During cancellation it keeps that label with a current-color spinner, disables repeated requests, and returns to “润色” only after the original task settles. Keep the button count and narrow-screen layout stable; cancelled late replies cannot replace the prompt. Tab uses native focus navigation; Enter generates and Shift+Enter inserts a newline, with IME confirmation protected.

Artwork generation and polishing use the automatic economy model. Artwork generation uses low reasoning effort; polishing uses none and disables tools. Each job receives task-specific instructions, low verbosity and no reasoning summary. The renderer does not supply a model override. Results return the actual task model, which is reported back to the renderer. A real GPT-6 Luna artwork request was exercised on macOS and returned a 1536×1024, 24-frame sprite sheet in about 44 seconds; this is one sample, not a latency guarantee.

Missing/old CLI and non-ChatGPT login have actionable setup messages. Each Generate Animation action produces one animation; a text-only start first creates its reference image as described above. Cancellation or failure keeps the previous preview available. A cancellation terminates owned processes and releases the task slot. There is no automatic retry that could duplicate an image request. Invalid reference images, file-dialog cancellation, export failures, and damaged recovery data remain recoverable in the UI. GIF and WebP exports are decoded independently with sharp in tests; browser tests validate a 24-frame export.

The only banner permitted below the title bar is a confirmed Codex disconnection, following the current connection-state policy. Never use it for success, save cancellation, generation/export errors, recovery or persistence failures. Successful exports, cancelled native save dialogs and completed recovery/retry operations finish silently. Recovery choices belong inside the result pane; unsaved-material actions stay beside the composer and preserve retry/original-file export. Failures use plain inline text below the composer, without an Alert surface, status icon or dismiss button. Keep export progress on its action button. The export spinner inherits the primary button's foreground color (`color="current"`), since the default accent spinner disappears against the accent background. Keep the busy main button at full opacity while disabling repeat activation; generic disabled fading must not obscure its running status.

The export options popover shows format and size in adjacent, independently labelled single-selection menus. Offer 40, 80, 160, 240, 320 and 480 square pixels, starting at 320 each launch; changing format retains the selected size. Neither selection starts an export. GIF, animated WebP and video use the chosen dimensions and include them in the filename. Exports are decoded from the original sheet, preserving historical offsets in their original 360px coordinate system, rather than resizing the preview images. For a generated or restored sheet with five complete columns and a clipped sixth, recover the 20 intact frames when all five displaced vertical seams are detected consistently. Preview and export share this decoder, and normal sheets retain the full 24 frames. Generation prompts specify exact 256px grid boundaries and a fully visible final column. Keep the menu's own 4px inset and reset the wrapping Popover.Dialog padding to zero so generic dialog spacing does not stack around the compact menus. Rows use a 30px minimum height with a 2px gap.

Export filenames use a concise AI title describing the actual animation, for example `小猫伸懒腰-320px.gif`; original sheets use `小猫伸懒腰-原图.png`. Ask for 4–8 Chinese characters and enforce a maximum of 12 Unicode characters after removing unsafe filename characters. The generation turn returns the title as JSON metadata after creating the sheet; never draw the title on the image. Store `title` alongside the result, and carry it through generation and checkpoints. Existing untitled material is analysed from its actual sheet on first export with the same automatic economy model, with image generation and tools disabled, then cached on the current result. Do not derive titles from the currently edited prompt or make a new naming request for every format/size. The export button stays pending during naming; naming failure preserves the preview, reports an inline error and offers the ordinary retry action instead of exporting a generic filename. Browser previews can export already-titled results; untitled results require the desktop AI bridge. A real GPT-6 Luna title-only check of the built-in traffic-light sheet returned `红绿灯依次闪烁` (7 characters); the new-generation title contract is covered by fixtures rather than another real image-generation run.

## Validation limits

CI uses native OS runners to test the pure Node adapter, headless Chromium workflows and an invisible Electron window, then packages the result. CLI process fixtures test failures and isolation; they do not verify account entitlements. A real ChatGPT-authenticated Codex 0.164.0 was separately exercised on macOS for text and a 1536×1024 sprite sheet. Windows/Linux account login, graphics drivers, OS installer UX and every supported OS release still require device acceptance testing.
